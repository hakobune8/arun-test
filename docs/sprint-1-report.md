## 1. プロダクトコンセプト

### 1.1 概要
**タイトル**: `StarPioneer` — 新規性のあるインベーダーゲーム

**対象ユーザー**: コーダーやゲーム開発者、レトロゲームを愛する層  
**コアループ**: 敵の出現 → プレイヤーの回避・攻撃 → スコア獲得 → 難易度上昇  
**差別化要素**: 敵の出現パターンがプレイヤーの行動に連動して変化する「適応型AI」を採用。従来のランダム出現ではなく、プレイヤーの移動傾向を学習し、予測不可能な攻撃経路を生成する。

**非目標**:  
- マルチプレイヤー機能  
- 外部サービス依存  
- 複雑なストーリーモード

### 1.2 受入基準（Sprint 1）

## 3. QA証拠

### 3.1 ローカル検証
```bash
# ビルド検証
$ go build ./cmd/server/
→ 成功

# テスト実行
$ go test ./...
→ PASS: 全テスト通過

# ローカルサーバー起動
$ go run ./cmd/server/
→ サーバー起動、ポート8080でリスニング

# ヘルスチェック
$ curl http://localhost:8080/health
→ {"status":"ok"}

# ゲーム画面アクセス
$ curl http://localhost:8080/
→ HTMLレスポンス（ゲームタイトルと開始ボタンを含む）
```

### 3.2 Dockerビルド
```bash
$ docker build -t starpioneer:latest .
→ 成功（multi-stage build完了）

$ docker run -p 8080:8080 starpioneer:latest
→ コンテナ起動、/healthエンドポイント応答確認
```

### 3.3 CI検証
GitHub Actionsワークフローが以下のジョブを通過：  
- `build` — Goビルド成功  
- `lint` — gofmt/lintチェック通過  
- `smoke` — ローカルサーバー起動とヘルスチェック

## 4. 修正対応

| 問題 | 対応内容 |
|------|----------|
| ゲーム画面の初期表示でJSエラー | クライアントサイドJSの初期化順序を修正、DOM準備完了後にスクリプト実行 |

## 6. 既知の制限

1. **ゲームプレイ**: 敵の弾発射機能がないため、プレイヤーは回避のみで対応が必要  
2. **パフォーマンス**: 敵の数が10体以下に制限されている（Sprint 2で拡張予定）  
3. **モバイル対応**: キーボード操作に依存するため、モバイルデバイスでは未検証  
4. **Kubernetes**: Ingressは未実装（要件通り）。外部アクセスにはPortForwardまたはNodePortが必要
