# Sprint 1 レポート: ベースライン提供と初期検証

## 概要
Sprint 1 では、「新規性のあるインベーダーゲーム」の最小実用可能スライス（MVP）を構築しました。外部依存なしで動作する Go HTTP サーバー、軽量なフロントエンド、Helm チャート、および検証可能な製品契約（artifact-contract）をコミットしました。

## 提供されたベースライン
- **製品コンセプト**: シンプルでポップなインベーダーゲーム。コアループは「移動・射撃・衝突判定・スコア加算」に集約。
- **バックエンド (`server/`)**: 標準ライブラリベースの Go HTTP サーバー。ヘルスチェックエンドポイント (`/health`)、静的アセット配信、およびゲーム状態を管理する最小限の API エンドポイントを実装。
- **フロントエンド (`client/`)**: HTML/CSS/JS で構成されるシングルページ。Canvas を使用した実際のゲームループと、スコア表示・ゲームオーバー画面を提供。
- **デプロイメント (`charts/`)**: 自己完結型の Helm チャート（`charts/invader-game/`）。Deployment、Service、リソース制限、プローブ設定を含む。
- **ドキュメント**: `docs/artifact-contract.md` で成果物の接続契約を定義。README に主要なユーザー体験と検証コマンドを記載。

## QA 検証証拠
- **ローカルビルド**: `go build ./...` および `go test ./...` が正常にパス。
- **サーバー起動**: `go run server/main.go` でサーバーが起動し、`/health` が `200 OK` を返すことを確認。
- **フロントエンド表示**: ブラウザでルートパスにアクセスすると、ゲームタイトルとプレイ可能な画面がレンダリングされることを確認。
- **Helm チェック**: `helm lint charts/invader-game/` が警告なしで完了。テンプレートが構文エラーなくレンダリングされることを確認。
- **CI パス**: GitHub Actions ワークフローが lint、build、test ステージを通過。

## 実施した修正/リメディエーション
- 初期スキャフォールディング時に発生したパス不一致を修正し、`client/` のアセットが `server/` から正しく配信されるようにルーティングを調整。
- Helm チャートのディレクトリ構造を整理し、孤立した断片ファイルが残らないよう `charts/<name>/` 配下に再配置。
- README の検証コマンドが実際のファイル構造と一致するよう更新。
