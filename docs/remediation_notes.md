# Sprint 3 修正ノート (Remediation Notes)

## 概要
Sprint 2 までの QA 検証結果に基づき、リリース前に解決すべきブロック要因を整理し、対応方針を記録します。コード実装は行わず、計画段階のドキュメントです。

## 特定されたリリースブロック要因と対応方針

| ID | 問題概要 | 影響範囲 | 対応方針 | 優先度 |
|----|----------|----------|----------|--------|
| R01 | 製品コンセプトの統一性欠如 (README/UI/コード間で名称や差別化要素が矛盾) | ドキュメント、UI、Go コード | 単一の Product Brief を Source of Truth として再確認し、ラベルと UI 用語を統一 | High |
| R02 | 主要ユーザーパスの接続断 (ルートハンドラがプレースホルダーを返す、またはフロントエンドが別ディレクトリに隔離) | Go HTTP サーバー、静的アセット | `main.go` のルートハンドラから実際のゲーム UI/静的ファイルを直接提供するようにルーティングを修正 | High |
| R03 | CI/CD パイプラインの不安定さ (テスト失敗、lint エラー、ビルド検証のスキップ) | `.github/workflows/` | 失敗するテストを修正、lint ルールを適用、fresh checkout でのビルド検証を CI に追加 | Medium |
| R04 | Helm/Kubernetes マニフェストの検証不足 (ラベルセレクタ不整合、プローブ設定欠如、リソースデフォルト未設定) | `charts/`, `k8s/` | チャートテンプレートを検証し、`values.yaml` にリソース制限と liveness/readiness probe を追加 | Medium |
| R05 | ドキュメントの重複と冗長性 (README に手順を列挙、focused docs へのリンク不足) | `README.md`, `docs/` | README を短い入口に再構成し、詳細手順は `docs/operations.md` へ分離、リンク切れを修正 | Low |

## 検証計画 (Sprint 3 実施時)
- [ ] `go test ./...` および `go vet ./...` が fresh checkout で成功することを確認
- [ ] `docker build` および `docker run` でローカル起動とヘルスエンドポイント (`/health`) 応答を確認
- [ ] `helm template` でマニフェスト生成が正常に完了し、Kubernetes 仕様と整合することを確認
- [ ] ブラウザでルートパスにアクセスし、ゲーム UI がレンダリングされることを確認
- [ ] README、UI 表示名、コード内の製品名が `docs/product_brief.md` と一致することを確認
