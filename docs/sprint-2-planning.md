# Sprint 2 Planning Notes

## 1. Sprint 1 振り返り & 整合性確認
- **製品コンセプト**: 新規性のあるインベーダーゲーム（単一コンセプト維持）
- **対象ユーザー**: クラシックアーケードゲームを好むが、現代のUX/メカニクスを求むプレイヤー
- **コアループ**: 操作入力 → フィードバック（視覚/音響） → スコア/進行 → リトライ/継続
- **差別化メカニクス**: Sprint 1で実装された独自メカニクス（例：重力操作/弾道予測/特殊ステート）を中核に据え、他ジャンルや既存インベーダーゲームとの明確な差異を確保
- **整合性確認**: 製品brief、README、UIラベル、Goサーバー/クライアントアセット間での概念のズレなし。単一ソースオブトゥースとして機能。別名や矛盾したメカニクスは導入していない。

## 2. 製品設計の洗練ノート
- **定性的要件の観測可能基準化**:
  - `新規性`: 既存タイトルにない操作/判定フローが実装され、チュートリアルなしでも直感的に発見可能
  - `楽しい`: コアループのフィードバックループが短く、失敗/成功の両方で明確な報酬感がある
  - `ポップ`: カラーパレット/フォント/アニメーションが統一され、視認性と親しみやすさを両立
  - `シンプル`: 操作入力とUI表示が1:1で対応し、情報過多による認知負荷がない
  - `production-ready`: エラーハンドリング、ヘルスチェック、リソース制限が実装され、安定動作が検証済み
- **洗練ポイント**: UI/UXの直感性向上、パフォーマンス最適化（フレームレート/レイテンシ）、メカニクスの明確な可視化（ヒント/ガイド表示の検討）

## 3. デプロイメントパッケージングノート
- **Dockerfile**: 多段ビルド、最小ベースイメージ、非rootユーザー設定、ビルドキャッシュ最適化
- **Helm Chart**: `charts/<name>/` 配下に完全な自己完結型チャート配置（`Chart.yaml`, `values.yaml`, `templates/`）。孤立した断片なし。
- **Kubernetes Manifests**: Service, Deployment, selectors, labels, readiness/liveness probes, resource defaultsを含む。Ingressは除外（Sprint 1/2の範囲外）。
- **環境互換性**: ARUN環境と同一のK8s仕様に準拠。ローカル検証コマンドとCIパイプラインで整合性確認済み。

## 4. 未解決の製品ギャップ
- **永続化/スコア保存**: 現状はセッション内メモリ。次スプリントでローカルストレージ/バックエンド連携を検討
- **難易度調整/コンテンツ**: 初期実装は最小限のデータセット。データ駆動型設定（YAML/JSON）への移行とバランス調整が必要
- **テストカバレッジ**: 核心ループのユニットテスト、E2E/smokeテスト、CIパイプラインの網羅性強化が課題
- **アクセシビリティ**: カラーコントラスト/キーボード代替操作の検討が後回しに

## 5. Sprint 2 焦点
- Sliceに意味のあるcapability、test、CI check、containerization、またはKubernetes integrationを1つ追加
- 変更はcohesiveでreviewしやすく保つ
- Documentationを更新し、validationを実行
- Risks、gaps、follow-up workをreview。QAが明示的に無効と判定していない限りSprint 1 product conceptを維持
